# @mednet/css — справка для AI-агентов

Готовый CSS для страниц без React (статика, MODX, любые шаблонизаторы): компоненты [Basecoat](https://basecoatui.com) в стиле Maia в теме ЦНИИОИЗ, шрифт Montserrat и токены бренда. React-проекты берут `@mednet/ui`, а не этот пакет.

## Правила

1. **Подключение:** `<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@mednet/css@2/dist/mednet.min.css">` и, если нужны интерактивные компоненты, `<script src="https://cdn.jsdelivr.net/npm/@mednet/css@2/dist/mednet.js" defer></script>`. Либо скопируйте папку `dist/` из пакета целиком (шрифты в `dist/fonts/` подключены относительными путями). Только шрифты — `dist/fonts.css`.
2. **Разметка — классы и `data-`-атрибуты Basecoat:** `<button class="btn" data-variant="outline" data-size="sm">`, `.card` с `header`/`section`/`footer`, `.field` с `label` и полем. Список компонентов — документация Basecoat; живой пример — `demo/index.html` в пакете.
3. **Только для новых страниц и сайтов без Bootstrap и других CSS-фреймворков:** в `mednet.css` есть сброс стилей (отступы, списки, заголовки) и классы с именами Bootstrap (`.btn`, `.card`), они пересекутся. В существующий сайт подключайте не этот файл, а `@mednet/tokens` (`tokens.css`, переменные `--mn-*`).
4. **Tailwind-утилит (`flex`, `p-4`, `gap-2`) в файле нет** — только компоненты. Раскладку пишите своим CSS на переменных `--mn-*`.
5. **Цвета — только `var(--mn-…)`, не HEX** (stylelint из `@mednet/lint-config` это проверяет).
6. Браузеры: Chrome/Edge 109+ (в том числе Windows 7/8.1), Firefox 128+, Safari 16.4+. В Chrome 109 не работают лишь анимации открытия и авторазмер `textarea`.
7. **Тёмная тема:** `<html class="dark">` — именно на `<html>`: тёмные правила Basecoat привязаны к `html.dark`. По системной теме она сама не включается — класс ставит проект (скрипт без мигания — в README). Свой CSS на `var(--mn-…)` в тёмной теме перекрашивается сам.

Четыре типа приложений: публичные лендинги и отчёты (`PublicLayout`), внутренние инструменты, пользовательские сервисы, дашборды (последние три — `AppShell`).

Все пакеты `@mednet/*` выходят с **одной версией** — ставьте один мажор. Справка каждого пакета лежит в `node_modules/@mednet/<пакет>/llms.md`: читайте её до работы и выполняйте. Чего в ките нет — не изобретайте и не тащите чужое, а спросите владельцев.

## Линтеры — часть подключения, а не опция

Технические запреты — основная защита бренда: справка описывает правила, линтер их проверяет. Без `@mednet/lint-config` агент может незаметно уйти с бренда. **Ставьте его в каждый проект** с `@mednet/ui`, `@mednet/css` или `@mednet/tokens`.

```bash
npm i -D eslint@^9 stylelint @mednet/lint-config
```

**ESLint** (`eslint.config.mjs`). Next 16 — после конфигов Next:

```js
import { defineConfig, globalIgnores } from 'eslint/config';
import nextVitals from 'eslint-config-next/core-web-vitals';
import nextTs from 'eslint-config-next/typescript';
import mednet from '@mednet/lint-config/eslint';

export default defineConfig([
  ...nextVitals,
  ...nextTs,
  ...mednet,
  globalIgnores(['.next/**', 'out/**', 'next-env.d.ts']),
]);
```

Vite/React — вместо конфигов Next берите `typescript-eslint` (`npm i -D typescript-eslint`):

```js
import { defineConfig, globalIgnores } from 'eslint/config';
import tseslint from 'typescript-eslint';
import mednet from '@mednet/lint-config/eslint';

export default defineConfig([
  ...tseslint.configs.recommended,
  ...mednet,
  globalIgnores(['dist/**']),
]);
```

**stylelint** (`stylelint.config.mjs`): `export default { extends: ['@mednet/lint-config/stylelint'] };`. Не подключайте `stylelint-config-standard` — на Tailwind v4 он даёт ложные ошибки.

В `package.json` должны быть скрипты `lint` (`eslint .`) и `lint:css` (`stylelint "**/*.css" --allow-empty-input`).

**Что запрещено:** цветовые литералы (`#fff`, `rgb()`, `hsl()`, `oklch()`) и произвольные цвета Tailwind (`bg-[#…]`) в классах, `style` и CSS; UI-библиотеки (`antd`, `@mui/*`, `@mantine/*`, `@chakra-ui/*`, `bootstrap`, `react-bootstrap`); прямой импорт `radix-ui`, `@radix-ui/*`, `@base-ui/*`; иконки не из `lucide-react`.

**Что линтер не ловит** (проверяйте сами): цвет через переменную (`const c = '#fff'`), именованные цвета в `style`, `@apply bg-[#fff]`, динамический `import('antd')`.

**Порядок работы:** прежде чем объявить работу готовой, запустите `lint`, `lint:css`, проверку типов и сборку. Ошибки линтера исправляйте кодом; `eslint-disable` / `stylelint-disable` не добавляйте — нужное исключение согласуйте с владельцами кита.

## Бренд ЦНИИОИЗ: правила и концепции

Кит — дизайн-система ФГБУ «ЦНИИОИЗ» Минздрава России. Цель: любой новый прототип сразу в бренде, а уход с бренда технически невозможен (линтер + нет «чужих» цветов). Не перекрашивайте, не пересобирайте и не «улучшайте» бренд по своему вкусу.

**Цвет**

- Только токены кита: семантические классы (`bg-primary`, `text-muted-foreground`, `border-border`, `bg-destructive`) или шкалы бренда (`red`, `blue`, `green`, `yellow`, `orange`, `violet`, `beige`, `peach`, шаги 50–950; `graphite` — текст). Стандартной палитры Tailwind нет.
- Смысл: красный (лососёвый) — действие и энергия, поэтому `primary` — красный (кнопки и ссылки); синий — постоянство и честность; зелёный — развитие и рост; графит — весь текст. Ошибки и удаление — отдельный `destructive`, а не `primary`.
- Фокус-кольцо — синее (`ring`), намеренно не красное: красное на поле читается как ошибка валидации. Не меняйте.
- Дополнительные цвета (`yellow`, `orange`, `violet`, `beige`, `peach`) — «при необходимости», например в диаграммах; интерфейс строится на красном, синем, зелёном и графите.
- Если сверяетесь с брендбуком (PDF): HEX-подписи на стр. 12 — копипаст одного значения, им верить нельзя. Реальные цвета — только в `@mednet/tokens`.
- Контраст всех семантических пар проверен на WCAG 2.1 AA. Не подбирайте свои пары «на глаз» и не снижайте контраст текста.

**Типографика**

- Шрифт один — Montserrat: текст 500, заголовки 600/700. Другие шрифты не подключайте. Bebas Neue (промо-заголовки) в кит не входит — в нём нет кириллицы.
- Размеры — только классами шкалы кита (`text-h1`…`text-h4`, `text-lead`, `text-base`/`sm`/`xs`), без `text-[…px]`.

**Форма и движение**

- Форма уже задана стилем Maia: кнопки и поля — «пилюли», карточки — крупное скругление, мягкие тёплые тени. Не меняйте `rounded-*`, тени и отступы компонентов; отступы в своей вёрстке — стандартная шкала Tailwind (4 px).
- Анимации — из кита (кривая `--ease`, 150/250 мс); `prefers-reduced-motion` их отключает — не переопределяйте.

**Иконки, графика, логотип**

- Иконки — только контурные из `lucide-react`, одного стиля; залитые (filled) запрещены.
- Логотип — только компонент `Logo` (или оригинальный файл): не перерисовывать, не перекрашивать, не растягивать. Горизонтальный вариант — с дескриптором, вертикальный — без. Охранное поле — половина ширины знака. Логотипу-ссылке дайте `aria-label`, одиночному знаку — `title`.
- Фотографии — светлые, реалистичные; иллюстрации — в гамме бренда, без безликих и утрированных людей. Размытые цветные пятна и фирменный паттерн — только декор.

**Язык и тон**

- Интерфейс по-русски, `<html lang="ru">`. Тон текстов — «научпоп»: на фактах, но понятным языком, без канцелярита и без панибратства.
- Подписи, ошибки и подсказки для экранного диктора — тоже по-русски.

**Доступность**

- Каждому полю — `label`, каждой картинке — осмысленный `alt` (декоративной — пустой), интерактивные элементы доступны с клавиатуры, фокус виден. Публичные страницы — через `PublicLayout` (ссылка «Перейти к содержанию», `<main id="main">`).
- Версии для слабовидящих пока нет — не изобретайте свою.
- Тёмная тема есть: класс `dark` на `<html>`, цвета — только токены и семантические классы; свои тёмные цвета не придумывайте, `dark:`-оттенки поверх токенов не нужны.

**Чего в ките сейчас нет** (не имитируйте, спросите владельцев): Storybook, карты регионов РФ, авторизации и БД.

**Если кит не закрывает задачу:** сначала поищите в `llms.md` (компонент, блок, токен). Нет — спросите владельцев кита. Не копируйте компоненты в проект, не подключайте другие UI-библиотеки и не правьте вид компонентов через `className` с цветами.

## UX: правила и рецепты экранов

Эти правила действуют вместе с брендом и линтерами: бренд отвечает за вид, этот раздел — за то, как из компонентов собрать понятный экран. Компоненты названы по `@mednet/ui`; без React (`@mednet/css`) применяйте то же через классы и разметку. Обязательное помечено **M**, рекомендуемое — **S**. Линтер эти правила не проверяет — проверяйте сами, до сдачи работы.

### Доступность (цель — WCAG 2.2 AA)

- **M** Цель клика не меньше 24×24 CSS px (кроме ссылок внутри текста). Кнопки размера `xs` и `icon-xs` — нижняя граница, на мобильных берите крупнее.
- **M** Сфокусированный элемент не прячется под залипающей шапкой, баннером или чатом: проверьте обходом по Tab.
- **M** То, что делается перетаскиванием, можно сделать и кликом (кнопки «вверх/вниз», выбор в списке).
- **M** Не просите ввести повторно то, что человек уже ввёл в этом процессе: подставьте или дайте выбрать.
- **M** Вход: разрешите вставку пароля и менеджеры паролей; у капчи должна быть альтернатива.
- **M** Справка и контакты стоят на одном и том же месте на всех страницах.
- **M** Текст масштабируется до 200% без горизонтальной прокрутки; размеры — в `rem`/классах кита, не в `px`.
- **M** У страницы есть `<title>` с её темой; один `<h1>`; заголовки идут по порядку.
- **M** Анимацию и автообновление можно остановить; учитывайте `prefers-reduced-motion`.
- **M** Ошибку и статус нельзя передавать только цветом: рядом текст или значок.
- **M** У кнопок-иконок, полей и картинок есть доступное имя (`aria-label`, `alt`).

### Формы и ошибки

- **M** Подпись — над полем (`Field` + `FieldLabel`), не placeholder: он исчезает при вводе. Подсказка по формату — `FieldDescription`.
- **S** Связанные поля группируйте по 4–6 (`FieldSet` + `FieldLegend`/`FieldGroup`); между группами отступ больше, чем между полями.
- **M** Проверяйте при отправке, а не при уходе из поля. Исключение — подсказка во время ввода (счётчик символов, надёжность пароля). Не добавляйте `required` на поля и отключите браузерную проверку (`noValidate` на форме).
- **M** Ошибка стоит у поля (`FieldError` + `aria-invalid`) и говорит, что не так и как исправить: «Введите дату в формате ДД.ММ.ГГГГ», а не «Неверное значение». Не пишите «пожалуйста» и «извините».
- **M** Если ошибок несколько — сверху `Alert variant="destructive"` со списком ссылок на поля; фокус переносится на него; к `<title>` добавьте «Ошибка: ».
- **M** После ошибки введённое сохраняется. Лишние пробелы, дефисы и скобки в номерах и кодах убирайте сами; невозможные значения (месяц 13) отклоняйте.
- **M** Проверка на сервере обязательна; клиентская — только дополнение, и правила не должны расходиться.
- **S** Длинную форму завершайте экраном «Проверьте ответы» с возможностью изменить; после отправки покажите страницу результата: что произошло и что дальше.

### Загрузка, пусто, ошибка

Это три разных состояния; не смешивайте их.

- **M** Загрузка до 1 с — без индикатора. 2–10 с — `Skeleton` (страница; повторяет раскладку, не пустая рамка) или `Spinner` (отдельный виджет, карточка). Дольше 10 с или передача файла — `Progress` с оценкой времени.
- **M** Пока данные грузятся, не показывайте «ничего нет».
- **M** Пусто — `Empty`: что здесь будет, как заполнить и кнопка действия. Пустой контейнер без текста — ошибка.
- **M** Сбой — понятный текст, что случилось и что сделать, кнопка «Повторить». Не показывайте технические коды вместо объяснения.
- **S** Результат действия — `toast`, если он не требует решения; ошибку, которую надо исправить, — на месте, а не в тосте.

### Опасные действия

- **M** Лучше дать отменить действие, чем спрашивать подтверждение: (кнопка «Отменить» в `toast`). Подтверждение — только для необратимого и серьёзного, через `AlertDialog`.
- **M** В подтверждении назовите объект и последствие: «Удалить 3 файла?», а не «Вы уверены?».
- **M** Кнопки называются действиями («Удалить», «Оставить»), не «Да/Нет». Фокус по умолчанию — на безопасной.
- **M** Рутинные действия не подтверждайте: человек перестанет читать.
- **S** Для самого опасного и редкого — ввод слова подтверждения.

### Общие принципы

Видимость состояния (человек всегда понимает, что происходит); язык пользователя, а не системы; выход и отмена в любом месте; единообразие (одинаковое действие выглядит одинаково); предотвращение ошибок лучше сообщений о них; узнавание вместо припоминания; минимализм (лишнее убрать); помощь в исправлении ошибок; справка рядом с местом, где она нужна.

### Рецепты экранов

Если задача называется как строка ниже — соберите экран так, не придумывая своё.

- **Форма заявки или обращения.** `Field`-группы по 4–6 полей, кнопка отправки внизу, ошибки по правилам выше, экран «Проверьте ответы» для длинной формы, страница результата.
- **Список или таблица с поиском и фильтрами.** Поиск и фильтры над списком; пока грузится — `Skeleton` по раскладке таблицы; нет данных — `Empty` с действием; нет результатов поиска — `Empty` с «Сбросить фильтры»; постраничность — `Pagination`.
- **Дашборд с показателями.** Карточки `Card` в сетке; у каждой своё состояние загрузки (`Spinner` или `Skeleton`) и своё пустое состояние; цифра всегда с подписью и единицей измерения.
- **Лендинг.** `PublicLayout`; один `<h1>`, одно главное действие на экран; проверьте масштабирование до 200% и видимость фокуса под шапкой.
- **Вход в систему.** Поля логин/пароль, вставка разрешена, ошибка не уточняет, что именно неверно (безопасность), ссылка «Забыли пароль» на том же месте всегда.
- **Страницы ошибок.** «Не найдено» (что искали, куда перейти), «Сервис недоступен» (когда вернётся, как связаться), «Что-то пошло не так» (что сделать, кнопка «Повторить»). Везде — ссылка на главную и контакты.
- **Подтверждение опасного действия.** `AlertDialog` по правилам блока «Опасные действия».
