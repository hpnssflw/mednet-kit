# mednet-kit

Используй справку установленной версии кита из контекста изменяемого приложения.

Определи приложение по изменяемым файлам и действующим инструкциям проекта. Запусти helper этого skill через Node из каталога проекта:

    node <путь-к-этому-skill>/scripts/resolve-kit.mjs

При запуске из корня монорепозитория укажи приложение явно:

    node <путь-к-этому-skill>/scripts/resolve-kit.mjs --project apps/web

JSON содержит surface, точные версии, package roots, пути llms.md и публичные exports. При нескольких проектах выбери изменяемый; не смешивай сведения разных версий. При двух объявленных surface укажи --surface react|html|tokens согласно задаче. Ошибка разрешения или несовместимый contract требует устранения причины, а не установки latest.

Прочитай setup, бренд и применимые обязательные UX-правила из выданных llms.md, затем относящиеся к задаче API и примеры. Это legacy режим: helper не обещает structured metadata. API наследуемой библиотеки сверяй с её установленной версией, если справки кита недостаточно.

React использует @mednet/ui; HTML/CSS использует @mednet/css без обязательного React. Случайно доступный пакет другой surface не меняет выбранный стек. Не копируй палитру или API из другой версии, playground либо глобальных инструкций. Не выдавай отсутствующий export за возможность кита.

Проверь изменённый сценарий средствами проекта. Статическая диагностика не доказывает effective lint rules, загрузку шрифта, поведение focus, WCAG или Chrome109; для них нужны соответствующие реальные проверки. Helper ничего не устанавливает и не исполняет конфиги проекта.
