# Mednet Kit: правила для Design Director

Этот файл — переносимое представление действующих источников кита, а не новая редакция бренда. Срез и хеши указаны в [manifest.json](manifest.json). Значения и формулы находятся в [tokens.json](tokens.json), API — в [components.json](components.json).

<a id="status-model"></a>

## Статусы и область применения

- `existing-implementation` — факт исходников. Не означает полной проверки поведения в браузере.
- `existing-policy` — действующее документированное правило кита. У него может быть известный разрыв с реализацией.
- `proposed` — предложение аудита; не является обязательным стандартом и не разрешает менять UI.
- `unknown` — сведений недостаточно; значение `null` не заменяется предположением.

Идентификаторы правил введены для этого экспорта и перечислены в `manifest.ruleIndex`. Они не являются ранее опубликованным API npm-пакета. `M` и `S` в скопированной UX-справке сохранены: обязательное и рекомендуемое соответственно. Уровень `mixed` в индексе требует прочитать конкретные пункты, а не считать всю секцию обязательной.

Действующие инструкции проекта и явно разрешённые исключения сохраняют свою область действия. Экспорт не даёт разрешения менять бренд, устанавливать пакеты, переписывать AGENTS.md или отправлять данные приложения наружу. При конфликте нужно назвать конфликт, а не незаметно изменить норму.

## Известные разрывы и неполнота

1. Kit 2.2.1 выпущен через штатный Release workflow. Локальный dist заново собран из точного релизного коммита и побайтно сверен с опубликованными npm tarballs: совпали 190 файлов четырёх пакетов. Экспорт вычислен из этих исходников; точный коммит указан в manifest. Сам JSON/Markdown-контракт поставляется отдельным переносимым каталогом.
2. Политика reduced motion существует, но React Spinner/Skeleton сохраняют spin/pulse; literal durations overlays также не сводятся только к 150/250ms. Не объявлять всю библиотеку исправленной или доступной по факту наличия токена.
3. Светлая chart palette имеет пастельные цвета с контрастом ниже 3:1 на белом. Проверять необходимое визуальное кодирование конкретного графика; не затемнять токены автоматически.
4. Реальная геометрия и тени имеют описанные выше исключения. Это не поручение их нормализовать.
5. `components.json` содержит полный перечень публичных React-модулей и частично извлечённый props/state API. Отсутствие записи об inherited prop не означает, что его нет. Отсутствующий известный default остаётся unknown.
6. `stateEvidence` — свидетельство CSS/исходника, а не полный конечный автомат или подтверждение keyboard/screen-reader поведения. Зависимые сочетания props и доступность проверяются в приложении.
7. Полный HTML component registry, body-text research, Chrome109/browser matrix и совместимость конкретной версии Director этим экспортом не подтверждены.
8. Формулировки исходной справки «все semantic pairs проверены», «один шрифт», «анимации отключаются» ниже являются существующей политикой/описанием. Применять их с указанными границами: не все state compositions проверены, а mono/weight/motion exceptions присутствуют в коде.

## Предложения аудита — proposed, не принятые нормы

Здесь перечислено направление обсуждения, без новых действующих token values или props:

- **P-numeric:** обобщить применение tabular-nums, правое выравнивание и правила числовых ролей. Факт поддержки tnum не делает его обязательным на любом тексте.
- **P-spacing:** назвать semantic spacing roles поверх существующих utilities. Имена inline/field/group/section пока не являются токенами Mednet.
- **P-density:** описать стандартный, компактный и touch-профили. У кита пока нет общего density API; не передавать выдуманные `density`/`size="compact"`.
- **P-geometry:** решить судьбу mixed radius/shadow conventions после визуального пилота. Не менять существующие значения по инициативе Director.
- **P-chart:** оценить контуры, маркеры, patterns и доступное представление данных до изменения палитры.
- **P-contract:** versioned metadata/loader и безопасные install/sync/doctor остаются архитектурным направлением. Этот каталог — подготовленный переносимый снимок, не установка нового публичного package export или CLI.

Не принятые архитектурные решения из proposal: **A1** — публичный контракт/CLI; **A2** — density/touch; **A3** — новые начертания/типографика; **A4** — radius/shadows; **A5** — chart encoding; **A6** — владение extractor/playground; **A7** — разделение UX knowledge с Director; **A8** — registry/plugin каналы. Ни одно из них не считается одобренным этим экспортом.

### Existing: React setup

Source: `repo:packages/ui/llms/intro.md`

Справка по установленной версии `@mednet/ui` — React-компонентам дизайн-системы ЦНИИОИЗ. Читайте её перед тем, как писать интерфейс.

## Правила

1. **Стили — одна строка** в `app/globals.css`: `@import '@mednet/ui/styles.css';` (внутри Tailwind v4, тема бренда и классы компонентов). **Шрифт — вторая строка, в коде приложения** (корневой layout, `main.tsx`): `import '@mednet/ui/fonts.css';` — Montserrat (`@fontsource/montserrat`) ставится вместе с пакетом. В CSS через `@import` его не подключайте: Tailwind не перебазирует пути `url()`, и в Vite файлы шрифтов теряются.
2. **Импорт — по подпутям:** `import { Button } from '@mednet/ui/button';`. Корневой `@mednet/ui` тоже работает, но тянет все модули.
3. **Основа — Base UI, а не Radix.** Чтобы отрисовать часть компонента другим элементом, используйте проп `render`, **не** `asChild`:
   ```tsx
   <DialogTrigger render={<Button variant="outline" />}>Открыть</DialogTrigger>
   <SidebarMenuButton render={<Link href="/settings" />}>Настройки</SidebarMenuButton>
   ```
   **Ссылка, которая выглядит как кнопка**, — это ссылка с классами кнопки, а не `Button` с `render={<a />}` (Base UI навязывает кнопке семантику кнопки):
   ```tsx
   import { buttonVariants } from '@mednet/ui/button';
   <Link href="/reports" className={buttonVariants({ variant: 'outline' })}>
     Отчёты
   </Link>;
   ```
   Примеры из интернета с `asChild` переписывайте на `render`. Не ставьте `@radix-ui/*`, `radix-ui`, `@base-ui/react` напрямую.
4. **Цвета — только семантические классы:** `bg-primary`, `text-primary-foreground`, `bg-secondary`, `bg-muted`, `text-muted-foreground`, `border-border`, `border-input`, `bg-field` (заливка полей), `ring-ring`, `bg-destructive`, `text-destructive`, `bg-card`, `bg-popover`, `chart-1…chart-8`. Стандартная палитра Tailwind (`slate-100`, `zinc-500`…) удалена, а `red-500`, `blue-700` и другие шкалы — брендовые (из `@mednet/tokens`); hex, `rgb()`, `oklch()` и `bg-[#…]` запрещены линтером (`@mednet/lint-config`).
5. **Типографика:** заголовки — `text-h1`…`text-h4` (класс задаёт размер, межстрочный и вес: h1 — bold, h2–h4 — semibold; на телефоне размеры меньше), вводный абзац — `text-lead`, остальное — `text-base`/`text-sm`/`text-xs`. Размеры экран/телефон, px: h1 48/32, h2 36/28, h3 28/24, h4 22/20, lead 18/17, base 16, sm 14, xs 13. Шрифт — Montserrat. Своих `text-[…px]` и `font-*` на заголовках не добавляйте.
6. **Иконки — только `lucide-react`** (где искать иконки и API — раздел «Стек и где искать API» ниже).
7. **Корневой layout** (обвязка Base UI):
   ```tsx
   <html lang="ru">
     <body className="relative">
       <div className="isolate">
         <TooltipProvider>{children}</TooltipProvider>
       </div>
       <Toaster />
     </body>
   </html>
   ```
   `isolate` — порталы (диалоги, меню, подсказки, уведомления) всегда поверх страницы; `relative` — бэкдропы в Safari iOS 26+; `Toaster` (из `@mednet/ui/toast`) — один на приложение, вызов `toast.add({ title, description, type: 'success' })` из любого клиентского компонента. Доступное имя области — «Уведомления», кнопки закрытия — «Закрыть уведомление»; при составной сборке своё имя области можно передать через `aria-label` в `ToastViewport`. `TooltipProvider` (из `@mednet/ui/tooltip`) необязателен, он объединяет задержку подсказок.
8. **Календарь — по-русски:** `<Calendar locale={ru} />`, `import { ru } from 'react-day-picker/locale';`.
9. **Старые браузеры:** Chrome/Edge 109 (Windows 7/8.1) поддерживаются, если в `postcss.config.mjs` после `@tailwindcss/postcss` стоит `'@mednet/ui/postcss': {}`. Не работают там AI-компоненты `bubble` и эффект `shimmer` (относительные цвета, Chrome 119+) — не используйте их на публичных страницах.
10. **Свои компоненты склеивают классы через `cn` из `@mednet/ui/utils`**, а не через clsx/tailwind-merge: обычный tailwind-merge не знает размеров шрифта бренда и роняет `text-h3` рядом с `text-foreground`.
11. Компоненты кита не копируйте в проект и не правьте их стили `className`-ами с цветами: нужен другой вид — спросите у владельцев кита.
12. **Графики:** компоненты графика импортируйте из `recharts` (peer-зависимость, `npm i recharts`), обёртки — из `@mednet/ui/chart`; документация и `llms.txt` — раздел «Стек и где искать API» ниже.
13. **Peer-зависимости ставятся сами** (npm 7+, pnpm 8+): `recharts`, `lucide-react` (иконки), `react-day-picker` (календарь, `locale`). Если менеджер их не поставил (yarn, отключён `auto-install-peers`), установите вручную: `npm i recharts lucide-react react-day-picker`. Импортируйте их напрямую только из своего `package.json`.
14. **Линтеры обязательны:** `@mednet/lint-config` ставится в каждый проект вместе с китом (ESLint и stylelint, Next и Vite) — настройка и список запретов в разделе «Линтеры» ниже. Затем разделы «Карта пакетов» (что подключать в какой ситуации) и «Бренд ЦНИИОИЗ» (все правила и концепции бренда) — читайте их до написания интерфейса.
15. **Тёмная тема:** класс `dark` на `<html>` (скрипт без мигания и переключатель пишет проект — в README пакета); `dark:*` в компонентах привязан к классу `.dark`, а не к `prefers-color-scheme`. Цвета не раздваивайте `dark:`-классами: семантические классы (`bg-card`, `text-foreground`, `border-border`…) уже тёмные внутри `.dark`. `Logo` перекрашивает текст сам, красный знак остаётся.

## Бренд ЦНИИОИЗ: правила и концепции

Кит — дизайн-система ФГБУ «ЦНИИОИЗ» Минздрава России. Цель: любой новый прототип сразу в бренде, а уход с бренда технически невозможен (линтер + нет «чужих» цветов). Не перекрашивайте, не пересобирайте и не «улучшайте» бренд по своему вкусу.

**Цвет**

- Только токены кита: семантические классы (`bg-primary`, `text-muted-foreground`, `border-border`, `bg-destructive`) или шкалы бренда (`red`, `blue`, `green`, `yellow`, `orange`, `violet`, `beige`, `peach`, шаги 50–950; `graphite` — текст). Стандартной палитры Tailwind нет.
- Смысл: красный (лососёвый) — действие и энергия, поэтому `primary` — красный (кнопки и ссылки); синий — постоянство и честность; зелёный — развитие и рост; графит — весь текст. Ошибки и удаление — отдельный `destructive`, а не `primary`.
- Фокус-кольцо — синее (`ring`), намеренно не красное: красное на поле читается как ошибка валидации. Не меняйте.
- Дополнительные цвета (`yellow`, `orange`, `violet`, `beige`, `peach`) — «при необходимости», например в диаграммах; интерфейс строится на красном, синем, зелёном и графите.
- Если сверяетесь с брендбуком (PDF): HEX-подписи на стр. 12 — копипаст одного значения, им верить нельзя. Реальные цвета — только в `@mednet/tokens`.
- Контраст всех семантических пар проверен на WCAG 2.1 AA. Не подбирайте свои пары «на глаз» и не снижайте контраст текста.

**Типографика**

- Шрифт один — Montserrat: текст 500, заголовки 600/700. Другие шрифты не подключайте. Bebas Neue (промо-заголовки) в кит не входит — в нём нет кириллицы.
- Размеры — только классами шкалы кита (`text-h1`…`text-h4`, `text-lead`, `text-base`/`sm`/`xs`), без `text-[…px]`.

**Форма и движение**

- Форма уже задана стилем Maia: кнопки и поля — «пилюли», карточки — крупное скругление, мягкие тёплые тени. Не меняйте `rounded-*`, тени и отступы компонентов; отступы в своей вёрстке — стандартная шкала Tailwind (4 px).
- Анимации — из кита (кривая `--ease`, 150/250 мс); `prefers-reduced-motion` их отключает — не переопределяйте.

**Иконки, графика, логотип**

- Иконки — только контурные из `lucide-react`, одного стиля; залитые (filled) запрещены.
- Логотип — только компонент `Logo` (или оригинальный файл): не перерисовывать, не перекрашивать, не растягивать. Горизонтальный вариант — с дескриптором, вертикальный — без. Охранное поле — половина ширины знака. Логотипу-ссылке дайте `aria-label`, одиночному знаку — `title`.
- Фотографии — светлые, реалистичные; иллюстрации — в гамме бренда, без безликих и утрированных людей. Размытые цветные пятна и фирменный паттерн — только декор.

**Язык и тон**

- Интерфейс по-русски, `<html lang="ru">`. Тон текстов — «научпоп»: на фактах, но понятным языком, без канцелярита и без панибратства.
- Подписи, ошибки и подсказки для экранного диктора — тоже по-русски.

**Доступность**

- Каждому полю — `label`, каждой картинке — осмысленный `alt` (декоративной — пустой), интерактивные элементы доступны с клавиатуры, фокус виден. Публичные страницы — через `PublicLayout` (ссылка «Перейти к содержанию», `<main id="main">`).
- Версии для слабовидящих пока нет — не изобретайте свою.
- Тёмная тема есть: класс `dark` на `<html>`, цвета — только токены и семантические классы; свои тёмные цвета не придумывайте, `dark:`-оттенки поверх токенов не нужны.

**Чего в ките сейчас нет** (не имитируйте, спросите владельцев): Storybook, карты регионов РФ, авторизации и БД.

**Если кит не закрывает задачу:** сначала поищите в `llms.md` (компонент, блок, токен). Нет — спросите владельцев кита. Не копируйте компоненты в проект, не подключайте другие UI-библиотеки и не правьте вид компонентов через `className` с цветами.

### Доступность (цель — WCAG 2.2 AA)

- **M** Цель клика не меньше 24×24 CSS px (кроме ссылок внутри текста). Кнопки размера `xs` и `icon-xs` — нижняя граница, на мобильных берите крупнее.
- **M** Сфокусированный элемент не прячется под залипающей шапкой, баннером или чатом: проверьте обходом по Tab.
- **M** То, что делается перетаскиванием, можно сделать и кликом (кнопки «вверх/вниз», выбор в списке).
- **M** Не просите ввести повторно то, что человек уже ввёл в этом процессе: подставьте или дайте выбрать.
- **M** Вход: разрешите вставку пароля и менеджеры паролей; у капчи должна быть альтернатива.
- **M** Справка и контакты стоят на одном и том же месте на всех страницах.
- **M** Текст масштабируется до 200% без горизонтальной прокрутки; размеры — в `rem`/классах кита, не в `px`.
- **M** У страницы есть `<title>` с её темой; один `<h1>`; заголовки идут по порядку.
- **M** Анимацию и автообновление можно остановить; учитывайте `prefers-reduced-motion`.
- **M** Ошибку и статус нельзя передавать только цветом: рядом текст или значок.
- **M** У кнопок-иконок, полей и картинок есть доступное имя (`aria-label`, `alt`).

<a id="rule-ux-forms"></a>

Source: `repo:docs/agent-guide/ux.md`; original M/S levels retained.

### Формы и ошибки

- **M** Подпись — над полем (`Field` + `FieldLabel`), не placeholder: он исчезает при вводе. Подсказка по формату — `FieldDescription`.
- **S** Связанные поля группируйте по 4–6 (`FieldSet` + `FieldLegend`/`FieldGroup`); между группами отступ больше, чем между полями.
- **M** Проверяйте при отправке, а не при уходе из поля. Исключение — подсказка во время ввода (счётчик символов, надёжность пароля). Не добавляйте `required` на поля и отключите браузерную проверку (`noValidate` на форме).
- **M** Ошибка стоит у поля (`FieldError` + `aria-invalid`) и говорит, что не так и как исправить: «Введите дату в формате ДД.ММ.ГГГГ», а не «Неверное значение». Не пишите «пожалуйста» и «извините».
- **M** Если ошибок несколько — сверху `Alert variant="destructive"` со списком ссылок на поля; фокус переносится на него; к `<title>` добавьте «Ошибка: ».
- **M** После ошибки введённое сохраняется. Лишние пробелы, дефисы и скобки в номерах и кодах убирайте сами; невозможные значения (месяц 13) отклоняйте.
- **M** Проверка на сервере обязательна; клиентская — только дополнение, и правила не должны расходиться.
- **S** Длинную форму завершайте экраном «Проверьте ответы» с возможностью изменить; после отправки покажите страницу результата: что произошло и что дальше.

<a id="rule-ux-feedback"></a>

Source: `repo:docs/agent-guide/ux.md`; original M/S levels retained.

### Загрузка, пусто, ошибка

Это три разных состояния; не смешивайте их.

- **M** Загрузка до 1 с — без индикатора. 2–10 с — `Skeleton` (страница; повторяет раскладку, не пустая рамка) или `Spinner` (отдельный виджет, карточка). Дольше 10 с или передача файла — `Progress` с оценкой времени.
- **M** Пока данные грузятся, не показывайте «ничего нет».
- **M** Пусто — `Empty`: что здесь будет, как заполнить и кнопка действия. Пустой контейнер без текста — ошибка.
- **M** Сбой — понятный текст, что случилось и что сделать, кнопка «Повторить». Не показывайте технические коды вместо объяснения.
- **S** Результат действия — `toast`, если он не требует решения; ошибку, которую надо исправить, — на месте, а не в тосте.

<a id="rule-ux-destructive"></a>

Source: `repo:docs/agent-guide/ux.md`; original M/S levels retained.

### Опасные действия

- **M** Лучше дать отменить действие, чем спрашивать подтверждение: (кнопка «Отменить» в `toast`). Подтверждение — только для необратимого и серьёзного, через `AlertDialog`.
- **M** В подтверждении назовите объект и последствие: «Удалить 3 файла?», а не «Вы уверены?».
- **M** Кнопки называются действиями («Удалить», «Оставить»), не «Да/Нет». Фокус по умолчанию — на безопасной.
- **M** Рутинные действия не подтверждайте: человек перестанет читать.
- **S** Для самого опасного и редкого — ввод слова подтверждения.

<a id="rule-ux-principles"></a>

Source: `repo:docs/agent-guide/ux.md`; original M/S levels retained.

### Общие принципы

Видимость состояния (человек всегда понимает, что происходит); язык пользователя, а не системы; выход и отмена в любом месте; единообразие (одинаковое действие выглядит одинаково); предотвращение ошибок лучше сообщений о них; узнавание вместо припоминания; минимализм (лишнее убрать); помощь в исправлении ошибок; справка рядом с местом, где она нужна.

<a id="rule-ux-patterns"></a>

Source: `repo:docs/agent-guide/ux.md`; original M/S levels retained.

### Рецепты экранов

Если задача называется как строка ниже — соберите экран так, не придумывая своё.

- **Форма заявки или обращения.** `Field`-группы по 4–6 полей, кнопка отправки внизу, ошибки по правилам выше, экран «Проверьте ответы» для длинной формы, страница результата.
- **Список или таблица с поиском и фильтрами.** Поиск и фильтры над списком; пока грузится — `Skeleton` по раскладке таблицы; нет данных — `Empty` с действием; нет результатов поиска — `Empty` с «Сбросить фильтры»; постраничность — `Pagination`.
- **Дашборд с показателями.** Карточки `Card` в сетке; у каждой своё состояние загрузки (`Spinner` или `Skeleton`) и своё пустое состояние; цифра всегда с подписью и единицей измерения.
- **Лендинг.** `PublicLayout`; один `<h1>`, одно главное действие на экран; проверьте масштабирование до 200% и видимость фокуса под шапкой.
- **Вход в систему.** Поля логин/пароль, вставка разрешена, ошибка не уточняет, что именно неверно (безопасность), ссылка «Забыли пароль» на том же месте всегда.
- **Страницы ошибок.** «Не найдено» (что искали, куда перейти), «Сервис недоступен» (когда вернётся, как связаться), «Что-то пошло не так» (что сделать, кнопка «Повторить»). Везде — ссылка на главную и контакты.
- **Подтверждение опасного действия.** `AlertDialog` по правилам блока «Опасные действия».

## Линтеры — часть подключения, а не опция

Технические запреты — основная защита бренда: справка описывает правила, линтер их проверяет. Без `@mednet/lint-config` агент может незаметно уйти с бренда. **Ставьте его в каждый проект** с `@mednet/ui`, `@mednet/css` или `@mednet/tokens`.

```bash
npm i -D eslint@^9 stylelint @mednet/lint-config
```

**ESLint** (`eslint.config.mjs`). Next 16 — после конфигов Next:

```js
import { defineConfig, globalIgnores } from 'eslint/config';
import nextVitals from 'eslint-config-next/core-web-vitals';
import nextTs from 'eslint-config-next/typescript';
import mednet from '@mednet/lint-config/eslint';

export default defineConfig([
  ...nextVitals,
  ...nextTs,
  ...mednet,
  globalIgnores(['.next/**', 'out/**', 'next-env.d.ts']),
]);
```

Vite/React — вместо конфигов Next берите `typescript-eslint` (`npm i -D typescript-eslint`):

```js
import { defineConfig, globalIgnores } from 'eslint/config';
import tseslint from 'typescript-eslint';
import mednet from '@mednet/lint-config/eslint';

export default defineConfig([
  ...tseslint.configs.recommended,
  ...mednet,
  globalIgnores(['dist/**']),
]);
```

**stylelint** (`stylelint.config.mjs`): `export default { extends: ['@mednet/lint-config/stylelint'] };`. Не подключайте `stylelint-config-standard` — на Tailwind v4 он даёт ложные ошибки.

В `package.json` должны быть скрипты `lint` (`eslint .`) и `lint:css` (`stylelint "**/*.css" --allow-empty-input`).

**Что запрещено:** цветовые литералы (`#fff`, `rgb()`, `hsl()`, `oklch()`) и произвольные цвета Tailwind (`bg-[#…]`) в классах, `style` и CSS; UI-библиотеки (`antd`, `@mui/*`, `@mantine/*`, `@chakra-ui/*`, `bootstrap`, `react-bootstrap`); прямой импорт `radix-ui`, `@radix-ui/*`, `@base-ui/*`; иконки не из `lucide-react`.

**Что линтер не ловит** (проверяйте сами): цвет через переменную (`const c = '#fff'`), именованные цвета в `style`, `@apply bg-[#fff]`, динамический `import('antd')`.

**Порядок работы:** прежде чем объявить работу готовой, запустите `lint`, `lint:css`, проверку типов и сборку. Ошибки линтера исправляйте кодом; `eslint-disable` / `stylelint-disable` не добавляйте — нужное исключение согласуйте с владельцами кита.

## Карта пакетов `@mednet/*`: что подключать

| Ситуация                                                                 | Что подключать                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Новый React-проект (Next 16, Vite), любой из четырёх типов приложений    | `@mednet/ui` + `@mednet/lint-config`; токены приходят с `ui`, шрифт — `import '@mednet/ui/fonts.css'`                                                                                                                                                    |
| Страница без React: статика, MODX, любой шаблонизатор                    | `@mednet/css` (CDN jsDelivr `@mednet/css@2` или папка `dist/`) + `@mednet/lint-config` (stylelint)                                                                                                                                                       |
| Существующий сайт со своими стилями (Bootstrap 4, самописные темы, antd) | `@mednet/tokens`: `tokens.css` и **только переменные `--mn-*`** — имена без префикса (`--primary`, `--accent`, `--muted`) конфликтуют с чужими. Хардкод-цвета сайта замените на `var(--mn-…)`; в JS — `import { color, semantic } from '@mednet/tokens'` |
| Проект на Tailwind v4 без shadcn                                         | `@import '@mednet/tokens/theme.css';` — сбрасывает палитру Tailwind (`gray`, `slate`… пропадут, `red`, `blue` станут брендовыми)                                                                                                                         |
| Графики вне React                                                        | палитра из `@mednet/tokens/tokens.json`                                                                                                                                                                                                                  |

Четыре типа приложений: публичные лендинги и отчёты (`PublicLayout`), внутренние инструменты, пользовательские сервисы, дашборды (последние три — `AppShell`).

Все пакеты `@mednet/*` выходят с **одной версией** — ставьте один мажор. Справка каждого пакета лежит в `node_modules/@mednet/<пакет>/llms.md`: читайте её до работы и выполняйте. Чего в ките нет — не изобретайте и не тащите чужое, а спросите владельцев.

## Фирменные блоки и каркасы

Серверные компоненты: их можно рендерить в `page.tsx`/`layout.tsx` без `"use client"`.

#### `Logo`

`import { Logo } from '@mednet/ui/logo';`

| Проп              | Тип                                                                     | По умолчанию   |
| ----------------- | ----------------------------------------------------------------------- | -------------- |
| `variant`         | `'horizontal' \| 'vertical' \| 'mark'`                                  | `'horizontal'` |
| `title`           | `string` — доступное имя; без него логотип декоративный (`aria-hidden`) | —              |
| `className` и др. | атрибуты `<svg>`; размер — классом высоты                               | —              |

```tsx
<a href="/" aria-label="ЦНИИОИЗ — на главную">
  <Logo className="h-10 w-auto" />
</a>
<Logo variant="mark" title="ЦНИИОИЗ" className="size-12" />
```

#### `SiteHeader`

`import { SiteHeader } from '@mednet/ui/site-header';` — логотип со ссылкой на главную, навигация, действия.

| Проп       | Тип                         | По умолчанию |
| ---------- | --------------------------- | ------------ |
| `homeHref` | `string`                    | `'/'`        |
| `nav`      | `ReactNode` — ссылки        | —            |
| `actions`  | `ReactNode` — кнопки справа | —            |

```tsx
<SiteHeader
  nav={
    <>
      <Link href="/about">О проекте</Link>
      <Link href="/reports">Отчёты</Link>
    </>
  }
  actions={
    <Link href="/login" className={buttonVariants({ size: 'sm' })}>
      Войти
    </Link>
  }
/>
```

#### `SiteFooter`

`import { SiteFooter, CNIIOIZ } from '@mednet/ui/site-footer';` — реквизиты ЦНИИОИЗ по умолчанию (`CNIIOIZ`: `fullName`, `shortName`, `phone`, `email`).

| Проп             | Тип                                | По умолчанию                      |
| ---------------- | ---------------------------------- | --------------------------------- |
| `orgName`        | `string`                           | полное наименование ЦНИИОИЗ       |
| `copyright`      | `string`                           | `ФГБУ «ЦНИИОИЗ» Минздрава России` |
| `phone`, `email` | `string \| null` (`null` — скрыть) | телефон и почта ЦНИИОИЗ           |
| `year`           | `number`                           | текущий                           |
| `links`          | `ReactNode`                        | —                                 |

```tsx
<SiteFooter links={<Link href="/privacy">Политика конфиденциальности</Link>} />
```

#### `PublicLayout`

`import { PublicLayout } from '@mednet/ui/public-layout';` — лендинги и отчёты: ссылка «Перейти к содержанию», `SiteHeader`, `<main id="main">`, `SiteFooter`. Пропсы: `nav`, `actions`, `homeHref` (как у `SiteHeader`), `footer` (замена подвала), `children`.

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="ru">
      <body className="relative">
        <div className="isolate">
          <PublicLayout nav={<Link href="/about">О проекте</Link>}>{children}</PublicLayout>
        </div>
        <Toaster />
      </body>
    </html>
  );
}
```

#### `AppShell`

`import { AppShell } from '@mednet/ui/app-shell';` — инструменты, кабинеты, дашборды: боковая панель (shadcn Sidebar, сворачивается до иконок, Ctrl/⌘+B), верхняя панель, содержимое.

| Проп          | Тип                                                                         | По умолчанию |
| ------------- | --------------------------------------------------------------------------- | ------------ |
| `nav`         | `ReactNode` — `SidebarGroup`/`SidebarMenu` из `@mednet/ui/sidebar`          | обязателен   |
| `title`       | `ReactNode` — заголовок в верхней панели                                    | —            |
| `actions`     | `ReactNode` — правая часть верхней панели                                   | —            |
| `homeHref`    | `string`                                                                    | `'/'`        |
| `defaultOpen` | `boolean` — из cookie `sidebar_state`; при `output: 'export'` не передавать | `true`       |

```tsx
// app/(app)/layout.tsx
import { LayoutDashboard } from 'lucide-react';
import { cookies } from 'next/headers';
import Link from 'next/link';
import type { ReactNode } from 'react';
import { AppShell } from '@mednet/ui/app-shell';
import { SidebarGroup, SidebarMenu, SidebarMenuButton, SidebarMenuItem } from '@mednet/ui/sidebar';

export default async function AppLayout({ children }: { children: ReactNode }) {
  const defaultOpen = (await cookies()).get('sidebar_state')?.value !== 'false';
  return (
    <AppShell
      defaultOpen={defaultOpen}
      title="Мониторинг"
      nav={
        <SidebarGroup>
          <SidebarMenu>
            <SidebarMenuItem>
              <SidebarMenuButton render={<Link href="/dashboard" />} tooltip="Дашборд">
                <LayoutDashboard />
                <span>Дашборд</span>
              </SidebarMenuButton>
            </SidebarMenuItem>
          </SidebarMenu>
        </SidebarGroup>
      }
    >
      {children}
    </AppShell>
  );
}
```
