# Полная реализация примеров Mednet

> Сверка 2026-11-08: первоначальный план выполнен. Следующая галерея из восьми примеров и общее оформление реализованы по плану 2026-11-06 и интегрированы в main playground. Iframe и прежняя численность ниже описывают историческую фазу. Актуальный остаток — [current-status.md](../../current-status.md).

> Исполнение: `superpowers:executing-plans`, основным агентом. Субагенты не разрешены договорённостями проекта. Изоляция — отдельная копия сайта внутри `artifacts/design-director-examples/site`; рабочие изменения кита и действующая витрина сохраняются.

**Цель:** заменить 14 фрагментов шестью законченными интерактивными примерами, новой галереей и просмотром копируемого кода.

**Архитектура:** существующий Vite/React сайт; сценарии в `src/examples`, общий небольшой demo adapter, чистая модель данных и отдельный реестр метаданных. Полные экраны открываются в собственном viewport через iframe; реализации и исходники загружаются по запросу. Сначала готовая проверенная рабочая копия, затем перенос в `C:/A/mednet-playground/react` с проверкой отсутствия чужих изменений.

**Стек:** React 19, TypeScript, Vite 8, Tailwind 4, `@mednet/ui` 2.2.1, Base UI, Montserrat, Recharts; Node test runner и Playwright для проверок. Новый runtime UI framework не вводится.

**Спецификация:** [2026-11-05-examples-redesign-design.md](../specs/2026-11-05-examples-redesign-design.md). Владелец поручил продолжать до полной реализации 2026-11-05; направление прототипа сохраняется, рутинные решения принимаются исполнителем.

## Общие требования

- Работают все шесть сценариев: реестр, аналитика, многошаговая заявка, обращение, настройки, публичная программа.
- Только фактические API, компоненты и токены Mednet; Base UI `render`, без второй библиотеки и правки generated components.
- Данные синтетические; demo adapter не выдаётся за backend. Для копирования доступны все необходимые локальные файлы и инструкция замены adapter.
- Submit validation, `noValidate`, без native `required`, связанные ошибки, сводка/фокус/title, сохранение ввода, доступное восстановление.
- Проверяются 1440/768/390/320px, обе темы, 200% текста, клавиатура, применимые состояния. PNG должны быть открыты и осмотрены.
- Канонические URL `/docs/examples/:id`, полные экраны `/examples/:id`, старые адреса получают рабочие переходы.
- Компонентная документация и `src/demos` сохраняются; главная меняется в объёме зависимых превью и ссылок.
- Без push, публикации, deploy и изменений глобальных навыков. Запись в каталог сайта требует разрешения среды; перенос выполняется после подготовки проверенного результата.

## Особое внимание при ревью

1. Изменение фильтра/данных на последней странице: не остаётся пустая страница при существующих результатах; покрывает модель реестра и browser flow.
2. Несколько отправок и переход между шагами при сбое: нет повторной записи, потери ввода и устаревшего результата; покрывает заявка/settings flow.
3. Нулевая база сравнения и переключение периода: график, таблица, метрики согласованы, нет Infinity/NaN; покрывают model tests и аналитика.
4. Длинная кириллица, 200% текста, открытый Sheet: данные и действия остаются доступны, фон недоступен клавиатуре; покрывает матрица browser evidence.
5. Код и старые ссылки: комплект примера компилируется без внутренних файлов документации; старый адрес не ведёт к отсутствующему экрану; покрывают проверки комплекта и маршрутов.
