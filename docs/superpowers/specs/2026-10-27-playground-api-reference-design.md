# Справочник по API и превью в docs-сайте playground — дизайн

Дата: 2026-10-27. Объект: `C:\A\mednet-playground\react` (Vite + React 19, вне репозитория кита, не git). Кит не меняется.

## Проблема

1. На странице компонента повторяется раздел «Установка» (`src/docs/component-page.tsx`, `src/docs/blocks-pages.tsx`). Для пользователя он лишний: установка описана на странице `/docs/installation`.
2. Справочник по API неполный и местами вводит в заблуждение:
   - `scripts/gen-api.mjs` сканирует только `node_modules/@mednet/ui/dist/components/*.d.ts`. Брендовые блоки (`Logo`, `SiteHeader`, `SiteFooter`, каркасы) лежат в `dist/brand/` и в `api.json` не попадают. Страница `Logo` пишет «нет свойств, добавленных китом», хотя есть `variant`.
   - Генератор оставляет только пропсы, объявленные в самом ките, и выбрасывает унаследованные от Base UI. У 22 из 61 записей таблица пустая (`slider`, `progress`, `checkbox`, `input`, `table`, `tooltip`, …).
   - Собранное поле `doc` страница не выводит, колонки «Описание» нет.
3. Превью разных видов и состояний есть не у всех компонентов: файлы `src/demos/<id>--<slug>.tsx` есть у части (у `button` — 3, у `slider` — ни одного). Из страницы не понятно, из чего выбирать (`variant`, `size`) и как выглядят состояния.

## Решения (согласованы с владельцем)

| № | Решение |
| --- | --- |
| Р1 | Раздел «Установка» убирается со страниц компонентов и блоков. Страница `/docs/installation` и пункт сайдбара остаются. |
| Р2 | Справочник — полная таблица: и пропсы кита (`variant`, `size`), и унаследованные от Base UI (`value`, `onValueChange`, `disabled`, `render`, …) с типом, значением по умолчанию и описанием на русском. |
| Р3 | Превью — вручную по компонентам, как у shadcn. Покрытие защищено проверкой. |
| Р4 | Описания пропсов — русский словарь `api-ru.json` в playground. Общие пропсы описаны один раз, специфичные — по компоненту. |

## Дизайн

### 1. Страницы компонентов и блоков

- Удалить блок «Установка» из `component-page.tsx:128-136` и `blocks-pages.tsx:83-93`.
- Строку `e.extra` («Дополнительно: …» — доустановка вроде `recharts`) перенести в «Использование» одной фразой, чтобы информация не потерялась. У блоков тот же приём для `extra.join(' ')`.
- Сайдбар и страница `/docs/installation` без изменений.

### 2. Генератор API (`scripts/gen-api.mjs`)

- Источники: `dist/components/*.d.ts` и `dist/brand/*.d.ts` (не вложенные `brand/logo/*`). Для брендового модуля `id` — имя файла (`logo`, `site-header`, …), как в `registry.ts`.
- Пропсы: все свойства первого параметра компонента, кроме
  - `className`, `children`;
  - атрибутов HTML/SVG и DOM-событий, объявленных в `@types/react` (`id`, `style`, `onClick`, `aria-*`, …).
  Остаются пропсы кита, пропсы из `@base-ui/react` и из `cva` (`variant`, `size`).
- Для каждого пропса в `api.json`: `name`, `type`, `default`, `optional`, `source` (`kit` | `base-ui`), и `values` — список значений, если тип — объединение строковых литералов.
- Значение по умолчанию: для `cva` — из `defaultVariants` (как сейчас); для остальных — из `api-ru.json`, если задано.
- Описание пропса: `api-ru.json` (`components[id][prop]`), затем JSDoc кита для пропсов, объявленных в `@mednet/ui` (он уже на русском, например у `Logo` и `SiteHeader`), затем `common[prop]`. Английский JSDoc библиотек не используется.

### 3. Словарь описаний (`src/api-ru.json`)

```json
{
  "common": { "disabled": "Отключает компонент…", "render": "Подставляет свой элемент вместо стандартного…" },
  "components": { "button": { "variant": "Вид кнопки…", "size": "Размер…" } }
}
```

Поиск описания: сначала `components[id][prop]`, затем `common[prop]`. Проверка (`pnpm check:api`) падает, если у пропса в `api.json` нет описания.

### 4. Таблица на странице (`component-page.tsx` → `Api`)

- Колонки: «Свойство» (имя, `*` у обязательных), «Тип», «По умолчанию», «Описание». Значения-перечисления показываются отдельными чипами, дефолтное помечено. Пропсы кита — с бейджем «кит», остальные — «Base UI».
- Несколько частей компонента (`Tabs`, `TabsList`, `TabsTrigger`, …) — по таблице на часть, как сейчас.
- Фраза «нет свойств, добавленных китом» удаляется; если у части нет пропсов, часть не выводится.
- Пояснение про остальные свойства («передаются дальше на базовый элемент») остаётся.

### 5. Превью

- Для каждого компонента из `registry.ts` пишутся примеры `src/demos/<id>--<slug>.tsx` с `export const meta = { title, description }`: все значения `variant`, все `size`, состояния (disabled, invalid, loading, checked/unchecked, пусто, длинный текст), типовые сборки составных компонентов.
- `Logo`: три примера — `horizontal`, `vertical`, `mark`; описание каждого — где применять.
- Сначала составляется таблица покрытия (что есть / чего нет по каждому компоненту), согласуется, затем идёт массовое написание.
- Проверка (`pnpm check:demos`): если в `api.json` у компонента есть `variant` или `size`, для каждого значения должен быть пример, где оно встречается в коде (поиск `variant="<значение>"` / `size="<значение>"` в `demos/<id>*.tsx`); иначе падает. Исключения — в явном списке с причиной.

### 6. Проверка результата

- `pnpm gen:api && pnpm check:api && pnpm check:demos && pnpm build` проходят.
- Playwright (chromium из `apps/docs/node_modules` кита): обход всех страниц компонентов; нет заголовка «Установка», нет пустых таблиц API, у `/docs/components/logo` в таблице есть `variant` с тремя значениями; скриншоты для визуальной проверки.
- Перед началом — копия `react/src` (playground не под git).

## Вне объёма

- Изменения в ките (`packages/*`), включая JSDoc в сгенерированных компонентах.
- Статичная ветка `static/`.
- Раздел «Блоки» — кроме удаления «Установки» и проверки, что таблицы API на его страницах не пустые.
- Тёмная тема и чат-блок (отдельные планы).

## Риски

- Фильтр «HTML-атрибуты против пропсов Base UI» может выкинуть нужное или оставить лишнее; проверить на `slider`, `checkbox`, `tooltip`, `select` и скорректировать список исключений.
- Объём описаний на русском велик (≈58 компонентов); общий словарь сокращает его, остальное — по результатам `check:api`.
- Playground ставит `@mednet/ui` из tarball в `.tarballs/`: после правок кита tarball нужно пересобрать, иначе API устареет.
