# Карта «на чём строится кит» — дизайн

Дата: 2026-10-27. Затрагивает кит (`packages/ui`) и docs-сайт playground (`C:\A\mednet-playground\react`, вне репозитория).

## Проблема

Чтобы найти API компонента, нужно помнить: основа — shadcn/ui, поведение — Base UI, иконки — lucide, графики — recharts, слайдер — Embla, и т. д. В `llms.md` у каждого компонента есть ссылка на shadcn, но общей карты нет: иконки, графики и слайдер упомянуты вскользь без ссылок, Base UI, `cmdk`, `react-day-picker`, `input-otp`, `react-resizable-panels` не описаны. Агенту приходится гадать, куда смотреть за пропсами, которых нет в справке кита.

## Решения (согласованы с владельцем)

| № | Решение |
| --- | --- |
| Р1 | Один источник правды в ките, два потребителя: `llms.md` (для агентов) и страница docs-сайта. |
| Р2 | Состав — не только четыре названные библиотеки, а всё, куда реально приходится смотреть за API или что определяет вид и поведение. |

## Дизайн

### 1. Источник: `packages/ui/stack.json`

Массив записей, публикуется в пакете (добавить в `files` и в `exports` как `./stack.json`).

```json
{
  "id": "base-ui",
  "name": "Base UI",
  "package": "@base-ui/react",
  "group": "base",
  "role": "Поведение и доступность компонентов. Часть компонента подменяется пропом `render`, не `asChild`.",
  "docs": "https://base-ui.com/react/overview/quick-start",
  "llms": "https://base-ui.com/llms.txt",
  "when": "Пропсы и события компонентов, кроме `variant` и `size`: `value`, `onValueChange`, `disabled`, `render`.",
  "usage": "inside"
}
```

- `group`: `base` (основа), `lib` (функциональные библиотеки), `kit` (экосистема кита).
- `usage`: `inside` — внутри кита, напрямую не импортировать; `peer` — peer-зависимость, импортировать напрямую; `project` — ставится в проект отдельно.
- `package` — имя npm-пакета, по нему скрипт берёт версию. `llms` — необязательное поле, ставится только если ссылка проверена.
- Версии в файле не хранятся: скрипты берут их из `package.json` пакета (`dependencies`, `devDependencies`, `peerDependencies`) при сборке.

### 2. Состав записей

| Группа | Записи |
| --- | --- |
| `base` | shadcn/ui (стиль Maia, вариант Base UI), Base UI, Tailwind CSS v4, `tw-animate-css`, `class-variance-authority` |
| `lib` | lucide-react (иконки), recharts (графики, обёртки в `@mednet/ui/chart`), embla-carousel-react (слайдер), react-day-picker + date-fns (календарь), cmdk (`Command`), input-otp, react-resizable-panels |
| `kit` | `@mednet/tokens`, `@mednet/css`, `@mednet/lint-config`, Montserrat (`@fontsource/montserrat`) |

Не включаются: `@shadcn/react`, `lightningcss`, `svgo`, тестовые и сборочные зависимости — потребителю они не нужны. В записи каждой `lib` поле `when` называет компоненты кита, за которыми стоит библиотека (`carousel` → Embla, `chart` → recharts, `calendar`/`date-picker` → react-day-picker, `command` → cmdk, `input-otp`, `resizable`).

### 3. `llms.md`

- `scripts/build-llms.mjs` читает `stack.json` и версии, формирует раздел «Стек и где искать API» и вставляет его после `llms/intro.md`, до `llms/brand.md`.
- Раздел — таблица по группам: «Что» (имя + версия) · «За что отвечает» · «Куда смотреть» (docs, `llms.txt`) · «Когда». Под таблицей — правило: «Пропса нет в справке кита — ищите в документации основы (Base UI / shadcn), затем библиотеки из таблицы; не выдумывайте».
- Строки 6, 12, 13 в `llms/intro.md` (иконки, графики, peer-зависимости) сокращаются до ссылки на раздел, чтобы факты не дублировались.
- `llms.md` — сгенерированный файл; руками не правится, пересобирается тем же скриптом.

### 4. Проверка в ките

- Тест (`vitest`) на `stack.json`: у каждой записи заполнены обязательные поля; `package` с `usage` `peer`/`inside` есть в `package.json`; `docs` — валидный `https://` URL; `id` уникальны.
- `scripts/check-dist.mjs`: `stack.json` присутствует в собранном пакете; в `llms.md` есть раздел «Стек и где искать API».
- Ссылки в сеть тест не ходит; доступность URL проверяется один раз вручную при составлении файла.

### 5. Docs-сайт playground

- `scripts/gen-api.mjs` (или отдельный `gen-stack.mjs`) копирует `node_modules/@mednet/ui/stack.json` в `src/stack.json`; версии берутся из `node_modules/<package>/package.json`.
- Страница `/docs/stack`, пункт «Стек» в сайдбаре сразу после «Установки» (`nav.ts`), маршрут в `App.tsx`. Карточки по группам: название, версия, роль, «Когда смотреть», ссылки «Документация» и `llms.txt`, метка `usage`.
- На странице компонента — строка «Основа: Base UI · документация shadcn» со ссылкой на `/docs/stack` (стыкуется с планом справочника API; до его реализации строка не добавляется, если страница компонента меняется там).
- Страница обновляется вместе с версией `@mednet/ui` в playground.

### 6. Релиз и порядок

- Кит: changeset `patch` на `@mednet/ui` (новый файл в пакете и раздел справки; внешний вид и API не меняются). Версию и публикацию делает Version PR / `release.yml`, не вручную.
- Порядок: (1) `stack.json` + генерация `llms.md` + тесты в ките; (2) релиз; (3) страница в playground после обновления зависимости. До релиза страницу можно проверять, подставив локальный `stack.json`.

## Вне объёма

- Автоматическая проверка живости внешних ссылок в CI.
- Описание API самих библиотек: даём только указатель, куда смотреть.
- Правки сгенерированных компонентов, `brand.css`, `overrides.css`.

## Риски

- Ссылки `llms.txt` есть не у всех библиотек, часть адресов может измениться: поле необязательное, а проверка доступности — разовая вручную.
- Страница в playground зависит от релиза кита; пока он не вышел, используется локальный файл.
