# Шаблон `templates/astro` для простых страниц — дизайн

Дата: 2026-10-28. Затрагивает `templates/astro` (новый), `packages/create-app` (вопрос «какой стек»), docs. Идея записана в [backlog](../../backlog.md).

## Проблема

Все пресеты `templates/next` из [плана B](../plans/2026-10-15-pilot-b-template-cli.md), включая `landing`, это Next, React, сборка и Docker. Для визитки или информационной страницы это тяжело. `@mednet/css` (Basecoat на HTML-классах) лёгкий, но готового проекта-стартера нет: подключение, каркасы шапки и подвала и проверки каждый раз собираются руками.

## Решения

| № | Решение |
| --- | --- |
| Р1 | Целевой сценарий: новые лендинги и информационные сайты, без Bootstrap, с нуля. Добавление страниц на существующие сайты не входит (там остаются `@mednet/tokens` и `fonts.css`). |
| Р2 | Стек шаблона: Astro, статическая сборка, без JS на клиенте по умолчанию, стили из `@mednet/css`. |
| Р3 | Компоненты: готовы только каркасы (шапка, подвал, лэйаут) как `.astro`-файлы в проекте. Остальное (кнопки, карточки, формы) это примеры разметки в демо-странице и docs. Обёрток вроде `<Button>` нет. |
| Р4 | React-острова с `@mednet/ui` в первую версию не входят. Кому нужен сложный виджет, берёт шаблон `next`. |
| Р5 | Доставка: через `@mednet/create-app`, как шаблон `next`. |
| Р6 | В проект входят `AGENTS.md`, проверки, CI (GitHub и GitLab) и Docker (nginx для статики). |
| Р7 | Каркасы живут в шаблоне (файлы проекта), отдельного пакета `@mednet/astro` и фрагментов в `@mednet/css` нет. Исправления доходят до созданных проектов вручную. |

## Дизайн

### 1. Раскладка проекта

```
src/
  layouts/Layout.astro        каркас: SkipLink, шапка, <main id="main">, подвал
  components/
    SiteHeader.astro          логотип, nav, actions (слоты)
    SiteFooter.astro          реквизиты ЦНИИОИЗ, links (слот)
    Logo.astro                варианты horizontal, mark, vertical (SVG)
  styles/site.css             раскладка каркасов на --mn-*
  pages/index.astro           главная
  pages/components.astro      демо: примеры разметки основных компонентов
public/                       favicon
astro.config.mjs              output: 'static'
```

Файлы шаблона лежат в `templates/astro/{base, ci/<github|gitlab>}`, как у `templates/next`. В pnpm workspace шаблон не входит (в `package.json` плейсхолдеры `{{name}}` и `{{kitVersion}}`).

### 2. Каркасы

API повторяет `@mednet/ui` (`packages/ui/src/brand/site-header.tsx`, `site-footer.tsx`, `layouts/public-layout.tsx`):

- `SiteHeader`: `homeHref` (по умолчанию `/`), слоты `nav` и `actions`. Логотип `horizontal` с ширины `sm`, ниже `mark`. `aria-label="ЦНИИОИЗ — на главную"`, навигация с `aria-label="Основная навигация"`.
- `SiteFooter`: `orgName`, `copyright`, `phone`, `email` (`null` скрывает), `year` (по умолчанию год сборки), слот `links`. Реквизиты по умолчанию те же, что в `CNIIOIZ` (`site-footer.tsx`).
- `Layout`: `SkipLink`, `SiteHeader`, `<main id="main">`, `SiteFooter`; пропсы `nav`, `actions`, `homeHref`, `footer` как у `PublicLayout`.

Отличие от React-версии одно: в `@mednet/css` нет Tailwind-утилит, поэтому раскладка (контейнер `max-width`, отступы, сетка подвала, перенос навигации) пишется в `src/styles/site.css` обычным CSS. Размеры и цвета берутся только из переменных `--mn-*`, HEX не используется.

Логотип: SVG берутся из `packages/ui/src/brand/logo/` и переносятся в `Logo.astro` как есть. Источником правды остаются файлы кита, расхождение ловит проверка паритета (раздел 5).

### 3. Стили и скрипт

В `Layout.astro` подключаются `@mednet/css/dist/mednet.min.css`, `fonts.css` и `site.css`; `mednet.js` подключается только на страницах, где есть интерактивные компоненты Basecoat (диалог, выпадающее меню, вкладки). Версия кита в проекте: `^{{kitVersion}}`, как в `templates/next` (решение 8 плана B).

Поддержка браузеров не отличается от `@mednet/css`: Chrome/Edge 109+, Firefox 128+, Safari 16.4+.

### 4. Проверки, CI, Docker, AI-слой

- **`npm run check`:** `astro check` (типы), ESLint и Stylelint из `@mednet/lint-config`, Prettier с `prettier-plugin-astro`. Stylelint запрещает HEX и требует переменные `--mn-*`.
- **CI:** варианты GitHub и GitLab как у `templates/next`: `check`, затем `build`. Actions закреплены по SHA с комментарием `# vX.Y.Z` (те же SHA, что в `.github/workflows/ci.yml` кита).
- **Docker:** многоэтапный `Dockerfile`: сборка на `node:24-alpine`, раздача `dist/` из nginx. Только npm (`package-lock.json`, `npm ci`), как в плане B. Проверка здоровья: ответ `200` на `/`.
- **`AGENTS.md`:** правила для агентов: только классы `mednet.css` и разметка из `/components`; цвета и размеры через `--mn-*`; Tailwind-утилит нет; `bootstrap` и другие CSS-фреймворки не подключать; сложный виджет значит другой шаблон, а не добавление React.

### 5. Паритет с `@mednet/ui`

Каркасы существуют в двух реализациях, поэтому нужен тест. Пилотный прогон шаблона (как `pnpm pilot` для `next`) собирает страницу из шаблона и страницу на `@mednet/ui` (`PublicLayout`) и сравнивает вычисленные стили шапки и подвала в двух ширинах (мобильной и десктопной), по образцу `tests/parity.spec.ts`. Расхождение стилей валит пилот.

### 6. Интеграция в CLI

- В `@mednet/create-app` добавляется вопрос «какой стек» (`next` или `astro`) и флаг `--stack`. Для `astro` пресетов нет, вопрос про пресет пропускается.
- Логика сборки проекта (база, слияние `package.json`, подстановка `{{name}}` и `{{kitVersion}}`, `_gitignore`, `npm install`, `git init`) используется общая. Подстановка идёт в `package.json`, `README.md`, `AGENTS.md` и `src/layouts/Layout.astro`.
- Тесты CLI работают на фикстуре, реальный шаблон проверяет пилот.

### 7. Документация

- Страница docs «Новый проект» получает раздел «Простой сайт без React».
- Страница `/components` в самом шаблоне служит и примером, и источником для docs: разметка основных компонентов Basecoat в теме ЦНИИОИЗ.
- Раздел про стеки в `llms.md` (см. [карту стека](2026-10-27-kit-stack-map-design.md)) упоминает путь `@mednet/css` + Astro.

## Вне объёма

- React-острова и пресеты на них (Р4).
- Обёртки `<Button>`, `<Card>` и другие компоненты на `.astro`.
- Пакет `@mednet/astro` и HTML-фрагменты каркасов в `@mednet/css` (Р7). Вернуться к ним можно, если появятся статические сайты вне Astro (MODX, шаблонизаторы), которым нужны те же каркасы.
- Gatsby: проект почти не развивается (оценка по памяти, не перепроверялась); `@mednet/ui` в нём и так работает как обычный React-пакет.
- Web Components как третий слой.
- Деплой, хостинг и домены.
