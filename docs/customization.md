# Кастомизация и отступления от бренда

> **Статус: черновик подхода, не проверен на практике.** Ступени ниже описывают задуманный порядок действий. Работает ли каждая из них на реальном `@mednet/ui` и `@mednet/css` (в частности, перебивают ли переопределения токенов правила `brand.css` и `overrides.css`), пока не проверено. Проверяем на боевых задачах и правим этот документ по результатам: каждую ступень помечайте «проверено» с датой и проектом.

## Принцип

Кит ставится как зависимость и не копируется в проект (в отличие от shadcn/ui). Единообразие бренда важнее свободы правки компонента. Поэтому отступление от бренда — осознанное решение с учётом, а не молчаливая правка у потребителя.

## Два случая

| Случай | Что делаем |
| --- | --- |
| Бренд меняется для всех | Правка в ките, changeset `major` ([releasing.md](releasing.md)), потребители обновляются через `npm update` |
| Отступление в одном проекте | Лестница ниже, начиная с первой ступени |

## Лестница для проекта

Идите по порядку и останавливайтесь на первой ступени, которой хватает.

1. **Токены.** Переопределите `--mn-*` в своём CSS после подключения кита. Для одного блока или страницы — в узком селекторе (`.landing { --mn-primary: ... }`), глобально — в `:root`. Меняйте семантические токены (`--mn-primary`), а не шкалы бренда (`--mn-red-600`): семантика ссылается на шкалы, и цепочка алиасов подхватит изменение сама.
2. **Композиция.** `className` поверх компонента, проп `render` для смены элемента (не `asChild`), обёртка над компонентом в своём проекте.
3. **Свой компонент** на токенах из `@mednet/tokens`, если готового нет или он не подходит.
4. **В кит.** Если отступление нужно двум и более проектам или оно по сути поправка бренда — не копируйте его между проектами, а предложите изменение в кит (`minor` для нового варианта, `major` для смены вида).

## Правила учёта

- Проектное отступление записывайте в README проекта одной строкой: что изменено, почему, кто решил.
- Для двух и более проектов с одним и тем же отступлением заводите задачу на перенос в кит (ступень 4).
- Не правьте файлы в `node_modules/@mednet/*` и не копируйте исходники компонентов в проект.

## Контраст

Тест контраста в `@mednet/tokens` (WCAG 2.1 AA) проверяет только токены кита. Если вы переопределили цвета, проверьте свои пары текст/фон сами: обычный текст — не менее 4.5:1, крупный и элементы интерфейса — не менее 3:1.

## Что проверить на боевых задачах

- [ ] Переопределение `--mn-primary` меняет цвет и в `@mednet/ui` (`brand.css`), и в `@mednet/css` (`overrides.css`).
- [ ] Узкий селектор (`.landing { … }`) работает для обоих пакетов и не требует `!important`.
- [ ] `className` поверх компонента перебивает правила `brand.css`; если нет — какой порядок слоёв нужен.
- [ ] Нужна ли потребителю проверка контраста для своих пар (хелпер в `@mednet/tokens` или скрипт).
- [ ] Как работает поддержка Chrome 109 с переопределёнными токенами.
