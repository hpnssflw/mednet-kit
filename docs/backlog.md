## Шаблон `templates/astro` для простых страниц

Дата записи: 2026-10-27. Статус: описано в [спеке](superpowers/specs/2026-10-28-astro-template-design.md), не проверено, не начато. Решения и детали — в спеке; ниже исходная запись.

### Зачем

Сейчас готовые стеки такие:

| Стек    | Пакеты                                                 | Для чего                       |
| ------- | ------------------------------------------------------ | ------------------------------ |
| React   | `@mednet/ui` (React ^19.2, Tailwind ^4.3)              | Приложения, кабинеты, дашборды |
| Статика | `@mednet/css` (Basecoat на HTML-классах + `mednet.js`) | Новые сайты без React          |
| Любой   | `@mednet/tokens`, `@mednet/lint-config`                | Токены, линтеры                |

Все четыре пресета шаблона `templates/next` из [плана B](superpowers/plans/2026-10-15-pilot-b-template-cli.md), включая `landing`, построены на Next и React. Для визитки или информационной страницы это тяжело: нужны сборка, Docker и React на клиенте. Статика на `@mednet/css` лёгкая, но готового проекта-стартера нет, поэтому каждый раз приходится собирать подключение руками.

### Идея

Шаблон `templates/astro`, который создаётся той же командой `npm create @mednet/app`:

- Astro-проект со статической сборкой и без JS на клиенте по умолчанию.
- Стили из `@mednet/css` (токены, шрифты, компоненты), подключены в шаблоне.
- Каркасы шапки и подвала в виде `.astro`-компонентов на HTML-классах. Сейчас они есть только в `@mednet/ui` (`site-header`, `site-footer`, `public-layout`).
- Необязательный пресет с React-островами: `@mednet/ui` подключается только на страницах, где нужен сложный виджет (календарь, график, `Command`).
- Вопрос «какой стек» в CLI. Общую логику (`generate.ts`, слияние `package.json`, подстановка `{{name}}`) можно переиспользовать.

### Что известно

- `@mednet/css` не зависит от фреймворка, значит с Astro должен работать. Не проверено.
- Ограничения `@mednet/css` (см. README пакета), которые шаблон должен учесть:
  - в файле нет Tailwind-утилит (`flex`, `p-4`, `gap-2`), раскладка пишется своим CSS на переменных `--mn-*`;
  - `mednet.css` содержит сброс стилей и Bootstrap-подобные имена классов, поэтому подходит только для новых сайтов;
  - Chrome/Edge 109 поддерживаются.
- Автотеста паритета React и HTML нет: он жил в `apps/docs`, который удалён 2026-10-28.

### Открытые вопросы

- Как `mednet.js` ведёт себя в Astro, в том числе при переходах между страницами и в React-островах.
- Нужна ли отдельная Astro-интеграция или хватает подключения файлов.
- Нужен ли шаблон вообще или достаточно раздела в docs «Простой сайт без React» с копируемым примером.
- Нужен ли Docker. Статику проще раздавать обычным веб-сервером.
- Как называть и публиковать: отдельный шаблон в `@mednet/create-app` или отдельный пакет.

### Как начать

1. Пилотная проверка: одна страница на Astro с `@mednet/css` и один React-остров с `@mednet/ui`. Ориентир: час–два.
2. Если проверка прошла, написать спеку `docs/superpowers/specs/<дата>-astro-template-design.md`.
3. План реализации. Он зависит от завершения [плана B](superpowers/plans/2026-10-15-pilot-b-template-cli.md): CLI и публикация `@mednet/create-app` должны быть готовы.

### Что сознательно не делаем

- Gatsby: проект почти не развивается, `@mednet/ui` в нём и так работает как обычный React-пакет.
- Web Components как третий слой: два слоя (React и CSS+HTML) с паритетом поддерживать уже непросто.
